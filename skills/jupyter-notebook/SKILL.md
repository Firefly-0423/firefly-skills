# Jupyter Notebook

创建便于阅读、检查和按顺序重跑的 Notebook。适用于实验与教程两条路径；修改已有文件时优先小范围编辑，保留用户意图、单元格和附件。宿主工具与权限决定实际读写和执行范围。

本版改编自 OpenAI Jupyter Notebook Skill，是纯说明与参考文件版本，不附带生成脚本、模板、内核或 Notebook 编辑器。不使用原文的 CODEX_HOME 路径，也不下载并执行其助手脚本；任务中的 Notebook 通过当前可用工具在批准工作区生成。

## 选定产物

- 实验：问题、假设或探索目标、数据、比较和评价方式；按需读 `experiment-patterns.md`。
- 教程：读者、先修知识、学习目标和逐步演示；按需读 `tutorial-patterns.md`。
- 已有 Notebook：先读取实际文件，确认只调整叙述、修改代码还是需要执行。沿用现有格式与结构，按需读 `notebook-structure.md`。

明确请求就直接推进，只补问会改变内容、输出位置或执行范围的缺口。基础概念可以直接解释；论文证据与完整科研设计可按当前可用技能协作，不依赖其他技能一定已安装。

参考通过宿主 `read_skill_reference` 读取，ref 只填文件名，不带 references/。只读相关资料，不一次遍历所有附件。

## 生成与编辑

先确定实际输出路径，避免中文标题默认映射到通用文件名而误覆盖。用户已有目录与模板就沿用，未读取的模板不能声称已采用。生成新文件前检查目标是否存在；未经授权不覆盖既有文件。只改变请求涉及的内容，不为了套用模板删除用户单元格、图片附件或元数据。

Notebook 是 JSON；优先使用环境已有的 Notebook 编辑能力或 nbformat 读写与校验。没有相关库时可用可用语言的 JSON 序列化工具，按结构参考生成，避免手工拼接、转义和执行计数错误。不因本技能自动安装依赖。

将工作拆成小代码单元和简短 Markdown，说明每一步的目的、前提及如何解释结果。初始化需要的状态应出现在前面，不能依赖上次交互残留。新代码单元的 execution_count 为 null、outputs 为空；不要写入看似执行过的示例输出。

修改代码或上游数据后，受影响旧输出不再视为当前结果。保留原文件或历史副本，按任务范围清理／标记失效输出，并说明哪些单元尚需重新运行。只调整排版时不擅自删除历史输出或附件，也不能因保留输出而声称本次已执行。

## 验证与执行

交付前读 `quality-checklist.md`，先检查 JSON、Notebook 结构、单元格顺序、引用路径和元数据。nbformat.validate 等结构检查不执行代码，不能证明结果正确。

用户要求或任务已明确包含验证性执行时，检查实际内核、依赖、数据与工作目录。阅读现有代码，留意安装命令、联网、数据上传、文件改写和费用；只在当前授权范围内执行。未知来源 Notebook 不是自动可信代码，打开、转换或信任标记也不授予运行权。

环境支持时，从干净内核按顺序运行全部相关单元，记录真实内核／语言、依赖、输入、执行范围、错误或停止情况。仅有计数和旧输出不证明完整重跑；部分执行就按实际范围交付。缺少内核时提供结构已检查、尚未执行的文件和补足条件，不自行安装或改用远程服务。

## 交付

给出实际 Notebook 路径、用途、主要内容及已完成的检查。区分文件已生成、结构校验通过、代码片段检查、干净内核执行、结果解释和读者／科研验收；不能互相替代。说明未执行单元和仍缺的输入，不编造结果、耗时或验证状态。
