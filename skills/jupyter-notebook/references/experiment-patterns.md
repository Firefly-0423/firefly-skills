# 实验 Notebook

由 OpenAI experiment-patterns.md 改编；Firefly 版增加产物来源、执行状态及权限约定。

组织为问题与成功条件、初始化与配置、实验计划、最小基线、结果分析、下一步。探索性问题可以先说明观察目标，不必预先有最终结论。

- 在运行前明确比较对象、变量、指标与预算；结果出来后改变问题或指标时标为探索性调整。
- 在前部设置可复用配置、实际数据来源、依赖与适用的随机种子。固定种子不等于消除所有随机性或证明稳定性。
- 先做最小可运行例子，再扩展必要条件。数据、预算或评估方式不同就不能直接归因于某个方法改变。
- 每个代码单元尽量完成一个步骤，用邻近的 Markdown 解释目的、实际观察与局限；代码输出是观察，作者推断单独说明。
- 关键结果可整理成小表或指标字典，关联输入、配置与运行。旧输出、示意数据和真实测量分别注明，负结果与失败不隐藏。
- 最后说明继续、调整或停止的依据。到达用户资源边界就交付当前结果，不启动持续优化或额外付费任务。

未运行时可以写预期现象、验证步骤与空结果区，但必须标为预期或待执行，不能填入伪造的测量值。真实计算图使用实际数据，示意图不替代量化结果。

完整论文证据、消融或统计设计超出单个 Notebook 的任务时，可以与当前可用的研究能力协作；缺少相应技能不阻断基本 Notebook 生成。
