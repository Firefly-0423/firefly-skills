# Notebook 交付检查

由 OpenAI quality-checklist.md 改编；Firefly 版分别报告结构、执行与结果证据。

## 结构与内容

- 文件能被 JSON 解析，Notebook schema 校验通过；单元有序、必需字段和适用的 id 有效。
- 初始化、输入来源与配置在使用前出现；路径和环境条件说明清楚。
- 每个代码步骤配必要解释，结果附近有解读，避免不必要的大输出。
- 用户原单元格、附件和扩展元数据保留；请求范围内的修改清晰。
- 新建未执行代码单元的 outputs 为空、execution_count 为 null；旧结果与本次执行状态没有混用。

## 实际执行

- 只有在任务与权限允许时执行；先核对代码中的文件操作、安装、联网、上传、费用与资源范围。
- 确认实际内核可用。JSON 解析、nbformat 校验和磁盘上存在 kernelspec 都不能单独证明执行成功。
- 从干净内核自上而下运行；记录实际运行的单元、输入、环境与错误。中断、超时或缺少输入分别说明。
- 部分执行、将代码抽出后运行和真正通过 Notebook 内核执行分别标注；片段正确不能替代整个文档重跑。
- 旧执行计数、过去缓存输出和另一次运行日志不作为本次完整执行的证据。

## 交付范围

给出实际产物路径和实验／教程用途。说明文件生成、结构校验、代码核对、内核执行与结果解释各自状态。没有执行环境时交付有效的未执行文件与所需条件，不停在泛泛建议，也不自动安装内核或换云端服务。

结构与代码运行检查不能证明科学假设、统计可靠性或学习效果。保留待核查来源、未完成练习和局限；真实读者或科研用户未验收时明确说明。
