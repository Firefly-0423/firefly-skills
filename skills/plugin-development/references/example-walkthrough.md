# 最小工具和验收

用一个只在 Work、Code 提供的问候工具打通开发流程。以 Firefly 1.2.0 SDK README 的最小插件为基线，清单的 tools 声明 greet，入口在 activate(ctx) 中调用 ctx.tools.register，注册名称写 greet。给参数定义必填的 target 字符串；无效参数或执行前取消返回 not_executed，有效输入返回 succeeded 和结构化问候内容。先确认批准摘要能让用户理解实际操作。

在 SDK 的 createTestHost 中验证有效输入、参数错误和取消。按 SDK 示例构造调用，检查结果和未执行时的副作用。测试宿主只验证调用契约，继续校验和生成 .ffplugin。

在真实应用中按下列顺序检查：

1. 导入包后确认插件版本、SDK 兼容信息和默认停用状态，再明确启用。
2. 在 Work 或 Code 提出匹配请求，核对实际工具调用和返回结果。按实际权限配置检查审批及拒绝路径。
3. 停用后再次查看工具是否仍可用；带窗口的插件还需实际打开、关闭并重开窗口。
4. 记录具体步骤、观察和失败细节。CLI 校验、测试宿主和真实应用三类结果分别写明。

功能扩展先看目标分支 plugin-sdk/examples 里的对应例子，再对照实际 SDK 类型。需要网络、凭据或写入时，用测试账号和隔离数据验收。
